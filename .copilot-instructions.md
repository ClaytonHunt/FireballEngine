# Copilot Instructions

To ensure consistency and code quality, please adhere to the following guidelines:

## General Guidelines

- **Adhere to the SOLID Principles:**
  - **S**ingle Responsibility Principle
  - **O**pen/Closed Principle
  - **L**iskov Substitution Principle
  - **I**nterface Segregation Principle
  - **D**ependency Inversion Principle

- **Naming Conventions:**
  - Use meaningful and descriptive names for classes, methods, and variables.
  - Follow Uncle Bob's (Robert C. Martin) rules for clean code naming.

- **Prefer Simple Code Over Complex Code:**
  - Write clear and concise code.
  - Avoid unnecessary complexity.

- **Use Design Patterns Appropriately:**
  - Apply design patterns where they provide clear benefits.
  - Avoid over-engineering.

- **Use Best Practices:**
  - Follow industry best practices for coding, security, and performance.

## Frontend (React) Specific Guidelines

- **Prefer React Context and Hooks Over Redux:**
  - Use the Context API and Hooks for state management unless Redux is necessary.

- **Component Structure:**
  - Break down components into smaller, reusable pieces.
  - Use functional components.

- **Styling:**
  - Use CSS Modules or styled-components for scoped styling.

## Backend (C#) Specific Guidelines

- **Test Naming and Implementation:**
  - Use Gherkin-style naming for tests (e.g., `When_GivenInput_Then_ExpectedResult`).
  - Follow the "One File per Class" concept for tests.
  - Apply the Single Assert Rule in unit tests.
  - Use Arrange, Act, Audit, and Assert comments

- **Exception Handling:**
  - Use try-catch blocks appropriately.
  - Provide meaningful error messages and logging.

- **Async Programming:**
  - Use asynchronous programming patterns where appropriate.
  - Follow best practices for async/await.

## Testing Guidelines

- **Write Tests Alongside Code:**
  - Aim for high test coverage.
  - Use unit tests, integration tests, and end-to-end tests where appropriate.

- **Single Assert Rule:**
  - Each test should assert only one logical outcome.

## Additional Suggestions

- **Code Comments and Documentation:**
  - Write XML documentation comments for public members.
  - Keep comments up-to-date with code changes.

- **Code Formatting:**
  - Follow the project's code style guidelines.
  - Use linting and formatting tools to maintain consistency.

- **Avoid Anti-Patterns:**
  - Be aware of common coding anti-patterns and avoid them.

## Security Considerations

- **Input Validation:**
  - Always validate user input on both client and server sides.

- **Secure Coding Practices:**
  - Protect against common vulnerabilities (e.g., SQL injection, XSS).
